# GENESIS — уровень 2: алгоритмы и обучение

Отдельный репозиторий алгоритмов PISTOL GENESIS. Реализации алгоритмов, моделей и обучения вы добавляете самостоятельно. Сейчас здесь только контракт интеграции с уровнем 1.

## Три уровня

| Уровень | Ответственность |
|---|---|
| 1 — ядро | Выполнение, временное состояние, метрики, перенос через checkpoint |
| 2 — этот репозиторий | Алгоритмы, обучение, переносимое состояние алгоритмов |
| 3 — [genesis-level-3](https://github.com/kirillpistol/genesis-level-3) | Внешние источники информации и адаптеры |

## Подключение

Разместите свой доверенный Python-модуль в пакете `level2_algorithms`.
Модуль экспортирует `REGISTRY = {"your_algorithm": AlgorithmClass}`.

При запуске из папки ядра этот пакет должен быть доступен Python — установите свой пакет или добавьте корень репозитория уровня 2 в PYTHONPATH. Затем:

```sh
python -m level1_core.server --algorithm-module level2_algorithms.my_algorithms
```

После запуска отправьте `POST /algorithms/attach` с `{"name":"your_algorithm"}`.

## Контракт класса

| Член | Назначение |
|---|---|
| version | Строка версии алгоритма и схемы состояния |
| __init__(state=None) | Создание или восстановление |
| process(value) | Синхронная обработка JSON-значения; JSON-совместимый результат |
| state() | JSON-совместимое переносимое состояние |
| merge(state) | Необязательное объединение независимых обученных состояний |

Алгоритм должен проверять вход и восстанавливаемое состояние, не изменять состояние при ошибке и не оставлять фоновых задач после process().
Ядро не диктует способ обучения. Не включайте исходные записи в state(), если требуется работа без постоянного хранения данных.
Только агрегаты или веса, возвращённые state(), будут включены в checkpoint.

Обмен через `POST /exchange` принимает `algorithm`, `merge_id`, `version`, `state`.
Повтор merge_id отклоняется; пересечение обучающих выборок автоматически не выявляется.
Python-модуль исполняется как доверенный код, без песочницы. API не принимает исходный исполняемый код.
